# BERK KULA — website

Minimal bilingual (EN/TR) audio engineer portfolio built as a **static site** and prepared for GitHub Pages. No framework, database, npm dependencies, hosting fees, secret keys, or user-facing admin panel required.

## What's here

- Selected live projects and collaborations sourced from Berk Kula's supplied portfolio.
- Featured latest **Altın Hızma** mix card on the homepage. Spotify playback and the chronological recording/mixing archive live **only on `recordings.html`**, linked from the Album / Mixing card and top navigation.
- Three YouTube videos: DKTT / Batuhan Aydın & Jülide Özçelik / Pinhani.
- Monthly event calendar, **pink = Türkiye, blue = international**.
- **Past shows automatically hidden**, never removed from `data/concerts.json`.
- Event credits include role (`FOH Engineer`, `Monitor Engineer`, etc.).
- Latest mix updates and video updates through editable JSON, terminal or GitHub issue forms.
- Annual report for each previous year as JSON, automatically generated by GitHub Actions on January 1 (subject to GitHub Actions scheduler delays).

## Start locally

```sh
cd berkkula-site
python3 -m http.server 8080
```

Open http://localhost:8080. **Do not open `index.html` with a file:// address** — the browser blocks fetch of JSON from local files.

## Publish using GitHub Pages

1. Create a GitHub repository and upload all these files (including the `.github` folder) to its default `main` branch.
2. In repository **Settings → Pages → Build and deployment**, select **GitHub Actions**.
3. In **Settings → Actions → General**, confirm workflow permissions permit the content-update and annual-report workflows to commit changes. The workflow specifies `contents: write`, but organization-level policies can override it.
4. Let **Publish website** complete. The Actions run shows the public site URL.
5. **Do not change Wix DNS yet.** First verify the GitHub Pages staging site. Only after that, connect `berkkula.work` in **Settings → Pages → Custom domain** and apply the GitHub-provided DNS records in your DNS provider; preserve your email-related DNS records. Add a CNAME file only once the custom domain is configured.

Note: GitHub Pages may not be enabled for a private repository under every plan. This is a public-facing portfolio. The repository's `data/concerts.json` archive is **publicly accessible** if published in this form, even though old shows are hidden from the visual calendar. If you require private historic event records, add a private backend or move the archive to a private data store before publishing.

## Add concert via GitHub issue form (no coding)

Open **Issues → New issue → Add concert** in the repository. Only a new issue created by the **repository owner** will be processed. A verified form will update `data/concerts.json`, commit the changes and close the issue. The site gets redeployed by `workflow_run` after the content workflow completes.

Example concert (example **only**, not included in the live data):

| Field | Example |
| --- | --- |
| Date | 2026-11-21 |
| Artist | Duman |
| City | Berlin |
| Country code | DE |
| Venue | Example Hall |
| My role | FOH Engineer |

Shows are sorted chronologically and only those on or after the current local date are displayed. The complete event record remains in the archive for reports, including old shows.

## Add latest mix / video via GitHub issues

- **Issues → New issue → Update latest mix:** replaces the highlighted song while retaining its predecessor in `mixHistory`.
- **Issues → New issue → Feature a new video:** new video goes to first position. Only the first three are displayed; older entries stay in the file.

To update through ChatGPT itself, **connect the GitHub plugin first** with write authorization to this repository. Then supply repo URL and instructions in the chat. A chat message *without* an active authorized GitHub connection does **not** edit the repository or the live website. Authorization and permissions are managed by GitHub/ChatGPT, not stored in this code. Changes should be checked after deployment.

## Terminal management alternative

```sh
python3 scripts/content.py concert --date 2026-11-21 --artist Duman --city Berlin --country DE --venue 'Example Hall' --role 'FOH Engineer'
python3 scripts/content.py mix --title 'Song name' --artist 'Artist name' --date 2026-12-01 --url 'https://www.youtube.com/watch?v=abcdefghijk'
python3 scripts/content.py video --title 'Video name' --artist 'Artist' --type 'Live mixing' --video 'https://youtu.be/abcdefghijk'
python3 scripts/content.py report --year 2026
```

Then commit and push the changed `data/*.json` files.

## Annual reporting

Workflow `.github/workflows/annual-report.yml` runs around **January 1, 06:30 Türkiye time** (03:30 UTC, subject to GitHub scheduling delays). It generates `data/reports/<year>.json` with:

- total concert count
- unique artist count, number of shows with each artist
- role breakdown
- Türkiye / international totals
- breakdown by country and month
- IDs of shows counted

The report is created from archived events, not currently visible events. No scheduled/upcoming concert counts as performed. To regenerate on demand, run the **Annual report** workflow manually with the desired year.
